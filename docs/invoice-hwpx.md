# 인보이스 HWPX

승인된 v4 양식은 `public/templates/invoice-master.hwpx`에 있습니다. BNI 머리 이미지는 각 구분 상단에, 명판은 첫 청구서의 입금계좌 표 오른쪽에만 들어갑니다. 청구서·예약확인서·취소규정은 각각 새 쪽에서 시작하며, 명단이 길면 다음 쪽으로 이어집니다. 표와 본문은 편집 가능한 한글 요소입니다.

`lib/invoiceHwpx.ts`는 양식의 7개 표(발신/수신, 예약정보, 청구금액, 계좌/명판, 예약확인, 명단, 취소규정)를 채웁니다. 표 구조를 바꿀 때는 이 매핑도 함께 수정해야 합니다. 양식에는 실제 고객정보가 없습니다. 취소규정은 기존 인보이스 내용을 유지합니다.

`components/InvoiceModal.tsx`의 두 생성 버튼은 같은 검증·저장 경로를 사용합니다. HWPX는 파일을 먼저 생성한 후 청구이력을 저장합니다. 저장 실패 시 다운로드하지 않습니다. 저장 성공 후 파일 전달이나 인쇄에 실패하면 저장본을 다시 출력할 수 있습니다.

‘방금 저장한 청구서’의 재다운로드·재인쇄는 저장 시점의 금액·명단·계좌를 사용하며 DB에 추가 기록하지 않습니다. 이 자료는 현재 열린 창의 메모리에만 유지됩니다. 창을 닫거나 예약을 바꾸거나 청구이력을 정정하면 제거됩니다. 기존 이력 전체를 복원하는 기능은 아닙니다.

검증:

- `node tests/invoices.test.cjs`: 기존 청구이력 검증
- `node tests/invoice-hwpx.test.cjs`: Playwright 및 Chrome이 필요합니다. 가상 API만 사용하며 실제 DB에 연결하지 않습니다. Playwright가 별도 위치에 있으면 `NODE_PATH`를 지정합니다.
- `npx tsc --noEmit --incremental false`
- `npm run build`

브라우저 검증에서 생성한 0·3·15·60명 가상 HWPX는 Git에서 제외되는 `coverage/invoice-hwpx/flow-*.hwpx`에 저장됩니다. 원본 v4의 배치는 사용자 확인을 받았습니다.

다인원 명단은 반드시 `treatAsChar=0`, `flowWithText=1`, `pageBreak=CELL`을 유지해야 합니다. 글자처럼 취급하면 표 전체가 다음 쪽으로 밀리고 하단 행이 가려질 수 있습니다. 이를 수정한 flow 파일의 XML·행 수·저장 동작을 재검증했고, 2026-11-03 사용자가 60명 수정본의 명단 이어짐을 확인하고 승인했습니다.
