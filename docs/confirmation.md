# 공통 HWPX 확정서

예약 관리에서 각 예약의 상세 화면을 열고 일정표(확정서) 항목의 `확정서 다운로드`를 누릅니다. 해당 예약만 대상으로 사용하며 취소 예약은 생성할 수 없습니다. 단체명은 예약자·거래처명으로 미리 채웁니다.

상품·날짜·인원·객실은 자동으로 채웁니다. 단체명, 피켓명, 현지가이드, 미팅 담당자/연락처를 입력할 수 있고 인원·객실·차량·미팅 시간/장소도 생성 전에 수정할 수 있습니다. 값은 이번 파일에만 쓰며 DB와 체크리스트를 변경하거나 파일을 서버에 업로드하지 않습니다. 다운로드 위치는 브라우저 설정을 따릅니다.

## 확장 구조

- `lib/confirmation/model.ts`: 목적지에 독립적인 문서 데이터, 날짜/매칭/집계 규칙.
- `lib/confirmation/products.ts`: 상품 어댑터 등록부. 현재 하문 고품격 3박5일, 관지산 4박6일을 홈페이지 자료에서 연결.
- `lib/confirmation/generateHwpx.ts`: 공통 표 생성, 일별/숙박별 행 수 계산, 한 페이지 높이 배분, ZIP 다운로드.
- `public/templates/confirmation-master.hwpx`: 고객·가이드·기존 일정·미리보기·작성자 정보를 제거한 공통 디자인 원본. 공개 가능한 빈 양식입니다.
- `components/admin/ConfirmationDownloadButton.tsx`: 대상 선택 및 입력창. 현재 세션의 Supabase 클라이언트로 객실 정보를 읽기만 합니다.

새 상품은 `ConfirmationProduct` 형태의 어댑터를 등록합니다. productSlug, variants, nights, days가 정확히 일치할 때만 자동 선택합니다. unknown/중복 매칭은 자동 선택하지 않습니다. 같은 목적지의 다른 코스를 기간만으로 대체하지 않습니다. 호텔은 실제 숙박일만 지정하고 기내숙박·해당없음은 null로 변환합니다. 날짜는 UTC 달력 연산으로 생성합니다.

홈페이지 자료의 미팅 시간/호텔 등은 기본값이며 직원이 수정합니다. `schedule`의 내용은 유지하고 빈 줄만 제거합니다. 포함/불포함/쇼핑/선택관광은 상품 어댑터에서 관리합니다. 새 상품을 등록하면 자동 적용되지만 실제 한글에서 1쪽 출력과 가독성을 반드시 검토합니다.

## 한 페이지

사용자가 확인한 양식과 같은 쪽 여백 및 총 표 높이 78,785 HWPUNIT을 사용합니다. 본문 9.5→9→8.5→8pt 순으로 필요한 최소 높이를 계산하고 남는 높이는 일별 본문행에 배분합니다. 내용이 최저 글자 크기에서도 넘치면 삭제/잘라내기 대신 오류를 반환합니다. 문서 엔진의 조판과 폭 추정은 다를 수 있으므로 저장·인쇄 전 실제 한글 확인이 필요합니다. 직원이 다운로드 후 수정한 파일은 자동 재조정하지 않습니다.

## 검증

`npm run test:confirmation` — 날짜 경계, 상품 매칭, 취소 제외, 인원 차이, 혼합 객실, 파일명 테스트.

개발 시 별도 로컬 브라우저 시험에서 실제 생성기를 실행했습니다. 3박5일/4박6일/다른 목적지 데이터, XML 문자 이스케이프, 미팅 담당자, 원문 일정 보존, 병합 누락·중복, 호텔행 개수, 총 높이, 과다 분량 오류를 확인했습니다. 입력창은 가상 예약/객실로 확인했으며 운영 DB를 이용한 실예약 시험과 배포는 별도입니다.

현재 지원 상품 이외에는 안내만 표시합니다. 예약 또는 객실이 최신 상태인지 확인하고 다운로드하세요. 객실 조회 실패는 직접 입력으로 보완할 수 있습니다. 타 예약과 공유된 객실은 자동 객실 수에서 제외하고 확인 문구를 표시합니다.
